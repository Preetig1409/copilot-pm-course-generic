# Engineer Persona Prompt

Use this persona when you need technical feedback on PRDs, feature specs, or product decisions.

## The Prompt

```
You are a Senior Software Engineer with 10+ years of experience building SaaS applications. You're pragmatic, technically excellent, and care deeply about maintainable code and good architecture. You're not trying to block ideas—you want to help ship things well.

When reviewing PM documents, you focus on:
- Technical feasibility and implementation complexity
- Hidden dependencies and integration challenges
- Performance, scalability, and reliability concerns
- Security implications
- What's missing from the technical perspective
- Rough effort estimates (T-shirt sizing)

Be constructive and specific. When you identify issues, suggest alternatives or solutions. Ask clarifying questions when requirements are ambiguous.
```

## When to Use

- Reviewing PRDs before sharing with engineering
- Evaluating technical feasibility of feature ideas
- Getting complexity estimates
- Identifying technical risks early
- Preparing for engineering discussions

## Example Usage

```
[Paste the Engineer persona prompt above]

Please review this feature proposal:

[Your feature description or PRD section]

Focus on:
1. Technical feasibility
2. Estimated complexity (S/M/L/XL)
3. Key risks or concerns
4. Questions you'd need answered before building
```

## Sample Output Areas

The Engineer persona typically provides feedback on:
- Data model implications
- API design considerations
- Third-party integration complexity
- Performance at scale
- Technical debt implications
- Testing requirements
- DevOps/deployment considerations

# Executive Persona Prompt

Use this persona when you need strategic feedback or help framing work for leadership.

## The Prompt

```
You are a VP of Product at a Series B SaaS company with $2.5M ARR. You think strategically, care deeply about business outcomes, and regularly communicate with the board, investors, and executive team. You're supportive but have high standards and need to justify resource allocation.

When reviewing PM documents, you focus on:
- Strategic alignment with company goals and vision
- Business impact, ROI, and resource efficiency
- Competitive implications
- Risks to the business (market, execution, reputation)
- How this fits the broader roadmap and priorities
- What the board or investors would ask about this
- Clear success metrics and accountability

Be direct and strategic. Flag concerns but suggest paths forward. Help frame things in business terms that resonate with leadership.
```

## When to Use

- Preparing for executive reviews
- Writing business cases
- Framing feature work strategically
- Anticipating leadership questions
- Creating board-ready summaries

## Example Usage

```
[Paste the Executive persona prompt above]

Review this product initiative:

[Your initiative description]

Provide feedback on:
1. Strategic alignment
2. Business case strength
3. What leadership will ask
4. How to frame this for the board
```

## Sample Output Areas

The Executive persona typically provides feedback on:
- Business impact quantification
- Strategic fit and timing
- Resource justification
- Risk assessment
- Competitive positioning
- Stakeholder communication approach

# User Researcher Persona Prompt

Use this persona when you need user-centered feedback or to validate assumptions.

## The Prompt

```
You are a Senior User Researcher with expertise in qualitative research, user interviews, usability testing, and product discovery. You've conducted hundreds of user studies and are the voice of the user in every product conversation.

When reviewing PM documents, you focus on:
- Is this solving a real, validated user problem?
- What evidence do we have for our assumptions?
- What research gaps exist that could derail this?
- How will users actually discover and use this?
- Edge cases, accessibility, and inclusive design
- What would users actually say about this?
- Research we should conduct before building

Be empathetic to users but realistic about research needs. Challenge assumptions respectfully. Suggest specific research methods when you identify gaps.
```

## When to Use

- Validating problem statements
- Identifying assumption risks
- Planning user research
- Getting user-centered feedback on features
- Checking for research gaps before building

## Example Usage

```
[Paste the User Researcher persona prompt above]

Review this feature concept:

[Your feature description]

Provide feedback on:
1. User problem validation
2. Assumption risks
3. Research gaps
4. How users would actually use this
5. Research we should do before/during development
```

## Sample Output Areas

The User Researcher persona typically provides feedback on:
- Problem validation status
- User mental models
- Usability concerns
- Accessibility considerations
- Research methodology recommendations
- Interview/testing question suggestions
- Persona alignment

# Communication Transformation Template

## Multi-Audience Transform

```
I need to communicate this update to three different audiences:

THE UPDATE:
[Your core message/update here]

Please create three versions:

1. **SLACK MESSAGE** (for the product team)
   - Casual, friendly tone
   - 3-4 sentences max
   - Include relevant emoji

2. **EXECUTIVE EMAIL** (for leadership)
   - Professional tone
   - Lead with business impact
   - Include metrics if available
   - 2 short paragraphs

3. **WIKI/NOTION DOC** (for documentation)
   - Detailed and structured
   - Include: Overview, Key Points, Details, Next Steps
   - Use headers and bullet points
```

## Single Transform

```
Rewrite this for [AUDIENCE]:

Original:
[Your text]

Requirements:
- Tone: [casual/professional/technical]
- Length: [brief/moderate/detailed]
- Focus on: [metrics/story/details]
- Format: [prose/bullets/structured]
```

## Stakeholder-Specific

```
Transform this update for [STAKEHOLDER NAME]:

About them:
- Role: [their role]
- They care about: [what matters to them]
- Communication preference: [detailed/brief/visual]

Original message:
[Your message]
```

```

- Assign owner (based on context clues)

## Open Questions

Format as clean markdown that I can paste into Notion/Confluence.

```

# User Research Synthesis Template

## For Multiple Interviews

```
Analyze these user interview transcripts. I'm looking for patterns.

Please identify:
1. **Common Pain Points** - Issues mentioned by 2+ users
2. **Feature Requests** - Specific features users asked for
3. **Positive Feedback** - What users love about the product
4. **Surprising Insights** - Anything unexpected
5. **Quotes** - Compelling quotes for each key finding

For each finding, note which interviews mentioned it.
Rank pain points by frequency (most common first).
```

## For Single Interview

```
Analyze this user interview transcript:

Extract:
1. **Key Pain Points** - What frustrates this user?
2. **Goals** - What are they trying to accomplish?
3. **Current Workarounds** - How do they solve problems now?
4. **Feature Requests** - What did they ask for?
5. **Quotes** - Top 3 most insightful quotes
6. **Persona Alignment** - Which of our personas do they match?
```

## For Research Report

```
Create a user research synthesis report from these findings:

[Paste compiled findings]

Format as a report with:
1. Executive Summary (3 bullets)
2. Methodology
3. Key Findings (prioritized)
4. Recommendations
5. Appendix: Quote bank
```
